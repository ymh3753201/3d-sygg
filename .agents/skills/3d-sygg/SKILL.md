# 3D sygg

安装与首次配置见仓库 `docs/INSTALL.md` 和 `docs/CONFIGURATION.md`（发行包内也附带）。生图默认使用 Codex 内置 imagegen，也支持用户按接口文档配置独立图片 API（OpenAI 风格文件上传、Seedream 风格 JSON 与可配置异步查询）。使用独立图片服务时先读 [图片 API 接入](references/image-api.md)，安装时集中配置一次。

仅项目内安装。面向不同商品与行业，不预设食品、数码或任何品类；执行本 Skill 的 AI 负责理解用户商品图并设计广告，Python 负责落实方案和处理媒体。

美术基准：国际高端商业广告的概念、构图、材质与视听冲击力。商品保真约束用于保护身份，不应把方案压缩成静物扫光、模特轻摆和收尾淡字。批准的立体文字、图标与特效是可主动设计的画面元素。

用户只经历：**上传商品图 → 确认方案 → 确认参考图并生成视频**。所有技术工作自动执行，不增加 Key 输入、参数选择或剪辑确认步骤。

效率原则：完整回归测试只在开发升级时运行，通道代表性实片验证只在首次接入或能力变化时执行；日常订单不重跑测试矩阵、不要求用户另做验收确认。已有合格通道经验由 AI 复用，合法时长、画幅和分辨率变化不单独触发付费验证。生产只做必要的文件/参数/预算检查和一次整片观看试听；轻微编码边界由本地剪辑自动处理。只有影响商品身份、关键创意、可播放性或消费授权的实质问题才阻塞，不以像素级复刻或主观完美为通过条件。

## 开始前

先读 [模型与长片能力](references/multi-model-long-video.md)，按具体通道的验证记录选策略。保留 Omni 原完整多宫格路径，三段叙事优先考虑效果好的三宫格；不把“支持多张图片”当作“宫格顺序实测通过”。

读取 [视觉与导演原则](references/visual-standards.md)、[参考图合同](references/omni-storyboard-guidance.md)、[人物决策](references/talent-strategy.md)；执行脚本时查 [工作流字段](references/workflow.md) 和 [API 与恢复](references/api-contracts.md)。安排声音时读取 [音色规则](references/voice-routing.md)。

先理解本次用户的商品、诉求、目标时长和投放场景，再用 Codex 原生视觉实际查看每张商品图；不能从文件名、历史项目或行业模板推断商品。图片必须有可读取的本地路径；没有就请求补图，不用相似商品代替。原商品照片只用于识别与所选图片模型的参考图输入，禁止登记为执行资产、临时公开或上传视频模型。

## 1. 上传商品图：完成方案，等待第一次确认

1. 分析本次图片所见的商品形态、结构、材质外观、配色、Logo、文字和不确定项；按钮、开口等只在实际存在时记录。区分图片能确认的事实、用户明确提供的信息和待确认项；不把推测的受众偏好或使用场景写成商品事实。不得猜测开启方式、内部结构、价格、成分、功效或销量。记录 `analysis.source_images` 全部绝对路径。
2. 成片时长由用户需求决定，支持非整十秒及小数秒，用户未指定时长时，AI 根据完整故事、镜头复杂度和旁白提出合适时长，写 `plan.target_duration` 与 `duration_reason`；不强制整十秒。用户指定秒数优先传入 `--target-duration`，否则由导演方案提供，绝不静默默认 10 秒。成片按 30fps 取最近一帧，并展示用户原秒数与实际帧数。从商品卖点、使用场景和受众决定 Big Idea、三类主风格之一、人物策略、运镜、声音、文字、时长和画幅。当前 wxart 支持 `9:16` / `16:9`；由投放场景决定，不能固定竖屏。是否出镜、露手、局部人物或完整模特，按用户要求与具体镜头需要决定；品类只是判断依据，不是强制开关。人物明确成年，服装和动作适配商品。一个广告可混合纯商品段和人物使用段：无人物段的 `talent_action` 留空，不上传人物图；有人物段写清动作，不强制每镜都露脸。
3. 按 [视觉与导演原则](references/visual-standards.md) 从商品的独特形状、纹理或真实动作提炼视觉资源，内部比较两个不同的表现机制后选出一个。`big_idea` 写明商品依据、可见事件和观众记忆；`style_rationale` 写材质/光影/图形的具体取舍；`story_arc` 写触发、发展、标志性瞬间与兑现。先形成完整创意，再分配片段任务。每段按需要选择 1–4 格，每格写叙事任务、构图、可见动作、真实商品细节、运镜与转场。单格适合连续镜头，多格适合时序叙事；不默认三格，不额外要求“单镜头许可”等重复标记。复杂度与节奏由导演判断，1–4 是本工作流范围，不是模型物理极限。镜头起态、动作结果、速度变化和转场对应要具体；不能用“高级、酷炫”代替事件。需要文字、图标或物理特效时用 `shots[].graphics` 写具体内容与空间动效，让同一份设计进入两类提示词和审阅页。积极设计批准标题参与场景，不局限于结尾淡入，不把禁止旁白字幕扩大为禁止广告图文。
4. 先设计整片，再按通道上限和叙事切分 `clips`。Omni 保留固定 10 秒、720p 请求；其他模型按 [能力表](references/multi-model-long-video.md) 的合法时长和清晰度生成。每段最多 1–4 镜，稳定 `shot_id` 全片唯一；超过上限就沿原镜头顺序增加段，不能丢弃视觉事件或每段重新开场。显式 `keep_duration` 总帧数减去 `overlap_before` 重叠帧数须等于成片帧数；省略保留时长时，脚本在已设计的段数内分配。默认 720p 成片，1080p 必须明确指定且通道可供；不静默改 Fast/Mini/其他模型。记录每段入场、出场、服装/场景/光线、衔接关系。延长不是无限单次生成，不启用未经接口与实片验证的 Extend。
5. 技术策略由 AI 自动选择，不交给用户填参数。Omni 默认保留完整宫格；其余通道自动复用已验证的执行能力：单画面可用于逐镜生成，多宫格须有时序样片依据；不按每个格数、时长或画幅逐项重测。文档支持但未实测时，先准备独立、有素材和金额上限的验证任务，不能拿普通订单默默试验。完整宫格/逐镜生成每段明确 `execution_reference_roles`，按 [参考图合同](references/omni-storyboard-guidance.md) 选择 1–3 张上传图及理由。第一张完整分镜控制叙事；可选母版约束商品身份，可选人物图约束成年人物身份。有序关键帧或首尾帧采用 `frame_prompts` 和稳定镜头编号，按同一创意直接生图，不能裁切批准宫格来节省未说明的调用。角色与顺序在第一次确认前决定；脚本仅在省略时提供启发式选择，必须读回并展示。
6. **默认直接使用视频模型输出人声、旁白/对白、音效、背景音乐和环境音，不调用 MiniMax 语音。** 用户说“需要旁白”“中文配音”仍走视频模型；只有明确说“单独使用语音模型配音/生成旁白”“使用 MiniMax 配音”等才走独立语音。默认 `audio.mode=video`、`narration.enabled=false`；这里 false 只表示不合成独立语音，不表示禁止视频人声。为每个生成片段写 `clips[].audio.speech_text`（需要的完整台词）、`voice`（全片统一的音色与表达）、`music`、`ambience`，并保留 `sfx` 的动作声设计。台词须来自方案，默认先提案自然中文广告语；无台词段不凭空说话。逐镜生成须用 `shots[].audio` 分配台词，不能每镜重复整段文稿。口播与画外旁白写明区别，仅需要人物开口的镜头安排口型同步。留出剪辑/转场余量，全部台词在保留区间内说完，不截断开口或尾字。`ad_copy` 只管理画面标题，不替代台词。只有用户明确请求独立语音时，记录 `audio.mode=external`、`audio.user_requested_external=true`，启用 `narration` 并查询当前 `system_voice`；视频保留音乐、环境音与音效，避免重复人声。详见 [语音与声音导演](references/voice-routing.md)。
7. 方案同时包含自动恢复额度：`recovery_policy.max_video_retries_per_clip` 默认 1（可设 0–3）。常规次数是展开策略后的实际生成段数；视频调用上限为段数 × (1 + 重试额度)，可通过 `budget` 进一步收紧。配置金额上限时必须附通道当前每次收费上界与核对日期；不把旧价目表当作现价。展示可能额外收费，不能把最多次数说成一定消费。明确失败只在原方案、原素材内重做失败片段，不重做成功段；该授权包含在现有两次确认中，不增加阶段。保存 analysis / plan JSON（prepare 会保留私有原图快照，避免临时附件失效），运行 `prepare --target-duration T`。读回 `plan.md`，展示商品判断、创意与风格理由、最值得记住的画面、全片故事、分镜时间与逐镜图文动效、素材角色顺序、画幅、广告文字、声音来源、批准台词、音色方向和付费次数。结尾只问：**确认方案，生成参考图**。

得到明确确认后运行 `approve-plan`；确认前不生图。

## 2. 确认方案：生成并展示实际参考图，等待第二次确认

1. 按方案冻结的 `reference_asset_plan.image_config` 选择生图：`builtin` 时读取 Codex `imagegen` Skill 并使用内置工具；外部 API 时按 [图片 API 接入](references/image-api.md) 运行 `image_api.py generate`，不得偷偷回退内置工具、换模型或伪造来源。第一次方案同时展示服务商、模型、输入照片传给谁、最低与最高图片调用数、当前费用；得到已有方案确认后执行。用 `product_master_prompt` 与全部原商品照片生成一张新的专业商品母版：商品完整、结构和标签准确、干净棚拍、不带广告特效/人物/分格，不复制原图背景。母版比例方便构图即可，不作为视频硬门槛。
2. 目视对照原图检查母版；人物模式另生成一张全局成年人物设定图。随后以母版（只有需要人物出镜的片段才加人物设定）为生图输入，依照 `reference_asset_plan.generation_order` 生成实际需要的完整分镜或独立关键帧。Omni 完整宫格仍整张使用；其他策略按 `frame_prompts` 单独生图，保留相同人物、商品、动态图文和动作。不得把广告海报兼作母版，不复制同一资产冒充多个角色。
3. 分镜应显示不同景别、动作进展、故事顺序与商品细节，并把每镜最关键的动作/图文/特效状态真正画出来；不能先生成普通商品摆拍，再期待视频模型凭空补出整套创意。母版的干净棚拍不限制广告场景。2–3 格单行左到右，4 格 2×2；每格比例不必等于成片比例。禁止编号、时间码、导演说明、旁白字幕；允许方案批准的品牌字和广告动效字。不要拆格、裁图或重新编码。
4. 每资产先生成一个候选。只有明确可见错误才做一次针对性修正；说明首版未采用及原因，只登记和展示最终待确认版本。不能因格式猜测或为导演说明重复付费生成同一图片。
5. 用 `register-references` 登记最终文件与生成关系。内置图片继续写 `origin=codex_imagegen`；外部图片写 `origin=external_image_api` 与脚本返回的 `generation_receipt`，不能填成内置来源。`identity_verified`、`clean_for_video`、`panel_order_verified`、`distinct_panels_verified` 必须来自实际目视核对。脚本验证来源声明、面板数、文件与解码像素重复、哈希和素材绑定；它不能证明主观画质或替代看图。有出镜的片段须记录使用的人物资产哈希；纯商品段不要求人物来源。
6. 在同一条用户可见回复中展示 `reference-approval.md` 对应的真实母版、人物设定（如有）及每段分镜。导演总览、时间与镜头意图放在图片外，不额外生图。逐段明确真正上传的图片顺序、职责，展示规格、音色和调用次数；临时公开仅覆盖此清单，不包括用户原图和未采用草稿。结尾只问：**确认参考图并生成视频**。

得到确认后运行 `approve-references`。更改方案、参考图、顺序、提示词、时长、音色或超出已批准恢复额度的次数，必须重新展示并确认；额度内的同素材失败重试不需要再确认，不在已有付费项目里覆盖旧批准记录。

## 3. 确认参考图：自动生成、剪辑、检查和交付

“确认参考图并生成视频”授权刚展示的调用次数和素材临时公开。运行 `produce`，它自动完成：

- 凭据、批准记录、真实文件与工具预检；不要求用户输入 Key，也不重复开启一个预检隧道。
- 默认不读 MiniMax 密钥、不查询其音色、不合成独立语音，直接保留视频模型生成的全部声音。只有用户明确要求独立语音配音时，短文稿合成一次整片 MiniMax `speech-2.8-hd`；长文稿用自然章节（每段不超过 2500 字符）及全片相对时间窗分段合成，统一音色语速。全部次数在第一次确认时列出；已有合格章节直接复用。音频不合格或超窗就停，不截断文稿，不消耗视频次数。
- 用一次隔离发布会话提供清单中的原文件，公网 GET 核对 SHA-256，保存发布过程证据。公网取图测试成功不等于供应商取图成功。
- 独立段最多两个并行。已验证首尾帧通道需要连续动作时，第一次方案写 `continuity_from`；实际提取前段保留区间末帧后，由 AI 查看商品、人物、动作并用 `review-continuity` 记录核对再恢复，不增加用户确认阶段。替换前段后必须重查后续依赖段，不传播错误。当前不开放短视频接续或原生延长的自动生产。
- 所有付费 POST 先记请求与账本。依次取得任务 ID 后并行等待，最多两个在途任务；任何提交不确定立即停止后续付费提交。明确返回 `failed/error` 的片段按已批准额度自动重试（默认一次）；明确 HTTP 429 拒绝也可有限重试。查询、下载故障先恢复原任务，不消耗新视频次数。
- 付费段和替换段都是素材；只有原项目全部片段齐全且批准声音素材完整后才进入后期。FFmpeg 按帧裁剪并统一至批准的 720p 或 1080p 成片规格；新版源片仅差一帧时在原有转码中自动补齐边界，成片容许一帧误差，不追加生成；切镜或叠化、保留音效，明确启用独立旁白时才按全片开口时间贴轨，讲话时自动压低背景，停顿和片尾保留音效；不截断文稿、不为凑时长机械加速。输出 `assembly.json`，记录全片各段来源与顺序、替换分镜审阅页和旁白音频。
- 输出 MP4、方案、参考清单、请求、任务账本、发布证据和技术 QA。技术通过进入 `awaiting_manual_review`；由 Codex 做一次整片观看试听，结合已有抽帧定位问题，检查方案标志性视觉事件是否兑现，以及商品与 Logo、顺序与动作、人物与手部、动态文字/图标/特效、声音和衔接。确认关键设计与质量达标后运行 `complete-review` 正式交付可播放 MP4；这由 AI 完成，不是第三次用户确认。无法实际试听或视觉不合格就如实标明待复核，不假称完成，不自动付费重做。

默认视频提示词必须包含声音设计和批准台词，不使用 `silent / no human voice / no speech` 禁人声约束。独立配音模式或用户要求无人声时，才禁止视频人声，仍生成背景音乐、环境音和音效。请求字段按对应接口文档发送：Seedance 沿用已适配的 `generate_audio=true`；Omni/H3 不添加未适配的开关。返回的视频须有覆盖保留区间的真实音轨；无声音时保留原任务、说明问题，不自动切换语音模型或重复收费。最终实际试听台词、音色、音效、音乐与跨段衔接，音轨存在不等于声音质量合格。

## 命令与恢复

在 Skill 根目录运行。用户只需表达商品、创意与时长；AI 负责执行命令。`configure` 与 `image_api.py configure` 只影响后续新项目，旧项目不迁移。生图配置/安全读 Key 检查：`python3 scripts/image_api.py check`（不联网、不计费；内置模式只报告无需 API Key）。

```bash
python3 scripts/commercial_ad.py capabilities
python3 scripts/commercial_ad.py configure --model omni
# 需要切换时可选 sd11-seedance-2.0 / sd11-seedance-2.5 / mm2-minimax-h3
python3 scripts/commercial_ad.py check-channel --model sd11-seedance-2.5
```

制作命令继续可用：

```bash
python3 scripts/commercial_ad.py prepare --project-id PROJECT --analysis analysis.json --plan plan.json --target-duration TARGET_SECONDS
python3 scripts/commercial_ad.py approve-plan --project outputs/PROJECT
python3 scripts/commercial_ad.py register-references --project outputs/PROJECT --manifest references.json
python3 scripts/commercial_ad.py approve-references --project outputs/PROJECT
python3 scripts/commercial_ad.py produce --project outputs/PROJECT
python3 scripts/commercial_ad.py resume --project outputs/PROJECT
python3 scripts/commercial_ad.py complete-review --project outputs/PROJECT --review creative-review.json
```

`produce` 与 `resume` 共用同一执行流程：复用已完成文件 → 查询已知未完成任务 → 按额度重试明确失败段 → 补齐尚未提交的原计划段 → 剪辑混音。同素材重试不得另建独立“补救广告”。确实需要修改分镜/提示词时，先展示局部改变、额外次数及它替换原片哪一段；已有授权直接执行，不重复询问。使用下面的原片绑定方式，不能仅在文件名写 clip2。默认每段最多 2 次视频请求（首次 + 1 次失败重试），多次运行不会重置额度。只有旧批准未包含恢复额度的历史项目保持查询模式，不自动扩大旧费用授权；历史文件不做自动迁移。语音保留整片已完成文件，不自动重做已付费语音；章节合成中断后只补尚未提交的章节。`submission_unknown`（断线后不知道是否创建/计费）、参数或鉴权错误、主动取消及额度耗尽不盲目重付费；保留项目与证据并简短说明阻塞点，不重新走创意流程。Quick Tunnel 会话关闭后原 URL 无法重建；新网址不能修复已提交请求。正常轮询期间保持服务，记录周期探测；退出清理公开素材但保留日志。通用 `generation_failed` 只记“原因未明”，不按文案猜测版权、人物或分格根因。

凭据按环境变量 → macOS 钥匙串 → 允许列表本地来源一次性迁移解析；不回显、不写入项目、不放入进程参数。默认 Omni 的规范模型 ID 是 `omni-fast-no-water`；默认 wxart 当前使用其目录别名 `omni-flash`，降级 Cangyuan 使用规范 ID。默认视频服务商仍是 wxart Omni；项目已配置 `ai.cangyuansuanli.cn` 作为降级服务商，只有默认服务商只读健康检查失败或明确的未创建任务拒绝才切换，提交不明不会盲目重付费。`setup_keys.py` 默认无交互，`--interactive` 仅用于用户主动要求的密钥维护。

### 修改片段后自动返回完整广告

只有实际需要改图/改方案且变更已获授权时，建立有归属的局部修订：

```bash
python3 scripts/commercial_ad.py prepare --project-id REVISION --analysis ORIGINAL_ANALYSIS --plan REVISED_SEGMENT_PLAN --target-duration KEEP_SECONDS --parent-project outputs/ORIGINAL --replace-clip 2
```

AI 按需要修改第几段填写索引，时长必须等于原片该段的保留时长；片段内部仍从 1 编号。复用 `reference_asset_plan.reusable_assets` 中的商品母版和适用人物图，只生成需要改变的分镜，不重复生母版。该修订沿用原来的方案/图片确认命令，审阅页明确最终仍交付原片总时长，局部项目不另合成旁白。

确认后对修订运行 `produce`，它保存替换素材，自动回到原项目，复用成功段与整片旁白，拼接、混音并返回原片最终路径。局部项目状态 `segment_ready` 仅代表素材就绪，不能运行 `complete-review` 当作独立成片交付。剪辑中断可对修订或原片 `resume`，无需再次生成。最终 `complete-review` 始终在原片执行，对照 `assembly.json` 中的实际分镜观看和试听；不能用局部 10 秒 QA 冒充全片验收。

没有原片绑定的历史补救目录不自动猜测归属或重写批准记录。本轮审查保留历史文件。以后制作必须从一开始绑定原片；不得通过关闭旁白、清空广告語或把原目标改成 10 秒来规避后续制作。供应商通用错误不能作为删品牌、删人物或删广告语的依据。
