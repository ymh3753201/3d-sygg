# 声音默认规则（schema 10）

默认 `audio.mode=video`：单段默认保留方案中的人物声或旁白、动作音效、环境音和背景音乐（BGM）；多段默认仅保留人物声或旁白与动作音效。无需 MiniMax 密钥，不查询其音色，不产生独立语音调用。视频模型 MiniMax H3 与独立 MiniMax TTS 是两类接口；选择 H3 视频不表示启用独立语音。

“需要中文旁白”“帮我配音”默认仍使用视频原生声音。只有用户明确要求“单独使用语音模型”“用 MiniMax 配音/生成旁白”时才启用 external。不要把普通旁白需求当作独立服务授权。

段数按执行策略展开后的片段数计算。单段完整宫格仍是一次生成，多段原片的局部替换继承整片规则。单段可在 audio.shared 或 clips[].audio 填 music 和 ambience；明确不要两种背景声时用 audio.omit_background=true。

## 默认方案写法

新项目优先使用 `audio.shared.voice` 统一文字声音方向，片段只补自己的台词和必要声音变化；不要求音频参考文件。不同角色可用 `audio.speakers` 配合 `clips[].audio.speaker_id`，同一角色全片沿用同一音色。完整字段、自动继承与长度检查见 [精简提示词](prompt-design.md)。旧项目不自动改写。

```json
{
  "audio": {"mode": "video", "speech": true},
  "narration": {"enabled": false, "text": "", "reason": "由视频模型直接输出声音"}
}
```

每段 `clips[].audio` 写 `speech_text` 与 `voice`，均为文字；`sfx` 继续对应镜头动作。需要旁白时，先提案自然中文完整台词，按故事分配到各段，保持音色、语速、品牌读音一致。没有台词的段让 speech_text 留空；明确不要人声时用 `audio.speech=false`。广告画内文字不自动变成朗读文稿。

逐镜策略 `per_shot` 在各 `shots[].audio` 写独立台词与声音方向，逐镜 sfx 可对应各自动作。脚本展开后继承本段说话人，每镜只保留自己的台词。不能把整段台词复制到每个生成镜头。其他策略用该段 clips[].audio。每句在实际保留区间内说完；有重叠转场时，把人声安排在非重叠部分，避免双声或剪掉词语。画外旁白不需要模特张嘴；只有批准镜头要求人物说话才安排口型同步。

多段画外旁白若要求同一个可辨识的声音，在首次方案中列出整片独立配音的音色、次数与费用，让用户随方案明确选择。Omni 没有声音参考输入；分段原生人声须逐段试听。Seedance 2.5、MiniMax H3 的音频素材额度已记录，但这里的适配器尚未验证上传与音色保持。提供了声音样本也不可默默上传或声称已使用。将来接入须先核对通道字段与限制，在有明确样本、公开范围和预算授权的验证项目中用同一份样本生成两段并试听，再用于客户订单。

## 输出检查

使用对应通道真实支持的声音字段，不臆造 API 参数。现有 Seedance 适配发送 generate_audio=true；Omni/H3 按已适配接口用声音提示词，不新增未知开关。有批准动作音效或原生台词的片段缺音轨或声音不足以覆盖保留区间时停止组装，保留任务，不自动调用独立语音补救。

明确无动作音效写 `sfx=""`。若已关闭背景且没有原生台词和逐镜音效，剪辑直接移除该段原声，可配合整片统一旁白；其余段保留模型原声。默认不再叠加 TTS，也不对原生人声单独二次压背景。实际试听整片：核对批准台词、品牌发音、人声清晰、音色统一、音效同步和声音衔接；单段核对批准的背景声音，多段核对没有配乐和环境底声。元数据只能证明音轨存在，不能证明说对了或好听。

## 独立语音开关

仅在用户明确要求时写 `audio.mode=external`、`audio.user_requested_external=true`，并启用 narration。也接受 `narration.user_requested=true` 作为用户请求记录。AI 不能自行填 true 来替代用户授权。已有 schema 7/8/9 项目不改变原合同；恢复时继续原批准的声音方案。

# 明确请求独立语音时：MiniMax 系统音色选择

先调用 `/v1/get_voice`，只把 `system_voice` 作为候选池。音色 ID 随账号和区域可能变化，因此规则按 `voice_name`、`description` 与 `voice_id` 的关键词匹配，不静默使用克隆音色。

## 默认匹配

| 广告内容 | 优先气质关键词 | 备选 |
|---|---|---|
| 科技、汽车、运动、硬核数码 | 播报男声、沉稳高管、可靠、低沉 | 专业男声 |
| 奢侈品、珠宝、香水、新冷调电影 | 沉稳高管、成熟、专业女声 | 新闻女声 |
| 美妆、家居、生活方式 | 温柔学姐、温暖闺蜜、柔和 | 亲切女声 |
| 青年潮流、玩具、饮品、时尚 | 清脆少女、不羁青年、活力 | 年轻声线 |

只有用户明确请求独立语音模型时才进入本节。普通“需要旁白/配音”由视频模型直接生成，不查询 MiniMax 音色或要求它的密钥。独立模式记录用户请求，开启 narration；单段保留批准的非人声设计，多段只输出动作音效，避免双重人声。

人物交互型科技、运动与青年潮流广告，旁白优先使用短句、略快节奏、沉稳且带轻微反差冷幽默；通常可在方案中选择 `speed=1.03–1.12`，但仍以试听自然为准。纯产品奢侈品和新冷调电影风应更克制，可降低语速或直接不使用旁白。冷幽默不能变成嘲讽用户，也不能制造图片中没有的功效、价格或品牌承诺。

## 选择边界

- 把选中的 `voice_id`、`voice_name` 和选择理由写进方案。
- 方案确认后，预检必须再次确认该 ID 仍出现在 `system_voice`。
- 如果音色失效，停止并让用户重新确认方案；不得自动换音色。
- 不读取或使用 `voice_cloning`、`voice_generation`，不调用上传或克隆接口。
- 文案用自然标点和少量 `<#0.2#>` 至 `<#0.8#>` 停顿，避免过度切碎语气。

## 全片声音设计与执行

先确定观众应记住的一件事，再写短句：感知钩子、经证实的产品价值、品牌/行动落点可以随画面分布，不是固定三句模板。不把隐喻写成未经证实的降噪、续航、疗效或价格。文稿不必逐字念画面标题，也不要不断描述观众已经看见的动作。

全片是一条声音时间线。`start_time` 决定开口点，`end_time` 是文稿最晚结束点（都以成片起点为 0），省略分别为 0/片长。给开场音效、主动作冲击和片尾品牌停顿留空间；例如 20 秒片可考虑 2–18 秒发声，但这是设计示例，不能机械套用。按选定音色的自然速度估算文稿，中文约每秒 3–4 字仅用于早期粗估，英文、数字和停顿需要另留余量。生成音频后以实际时长核对，超窗不能剪断旁白或盲目加速。

官方 `speech-2.8-hd` 默认整片合成一次，连续文稿靠自然标点和少量停顿表达节奏。MiniMax 内部停顿放在文字之间；不要为每个 10 秒视频单独合成、换声线或从头重复。先验证语音再启动视频，防止最后才发现文稿过长。已完成旁白按请求（文稿/音色/语速）与文件哈希复用，改一个视频段不重新消耗整片语音额度。

FFmpeg 在完整拼接画面上按开口点贴轨，旁白响度统一、讲话时背景压低、停顿与片尾恢复动作音效，限制混音峰值，不默认烧录旁白字幕。一个音轨存在不能证明旁白已生成：整片组装必须绑定批准文稿对应的 MiniMax 文件；最后实际试听发音、品牌字、自然语气、音效层次、起止和跨段连贯性。不能拿音频元数据当作听感验收。

参考：[MiniMax 官方同步语音](https://platform.minimaxi.com/docs/api-reference/speech-t2a-http)。模型和字段按官方能力核对，凭据与区域端点从现有安全配置读取，本轮不验证实号连通。

恢复时，若整片旁白已批准、额度为 1 且账本中从未尝试 MiniMax，即使视频已经生成，也会补齐首次语音合成后继续混音。已有语音尝试但结果不明或文件丢失时不能自动重复计费，更不能退化成无旁白交付。
