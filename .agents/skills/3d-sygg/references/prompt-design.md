# 短广告的分段、分镜与精简提示词

适用于新 prepare 的 `prompt_design_version=1`；项目 schema 仍为 10。旧项目没有此标记时不重建提示词、不更改批准记录。此设计不增加声音参考文件、付费调用或用户确认步骤。

## 先脚本，后段数

先根据用户业务目标、目标时长和脚本安排完整广告，再按所选通道单次时长上限决定一段或多段。单段能完整表达就单段；多段沿故事推进分配镜头，不重复开场、不复制动作凑时长。不因提示词太长自动增加付费段数。三宫格继续用于表达每段设计的构图、动作与效果；1–4 格仍按内容需要选择。

完整宫格模式每段上传自己的分镜，配上计划中适用的统一商品母版、人物图；不要因优化连续性默认改成逐镜或首尾帧生成。已有其他策略保留原能力限制。

## 每次请求只包含执行所需信息

分镜生图：版式与身份输入 → 本段美术/人物 → 入出场及相邻边界 → 每格构图、动作状态、商品细节、运镜与图文效果 → 必要画面限制。

视频生成：真实上传图的顺序与职责 → 统一身份与美术 → 本段边界 → 逐镜时间和动作 → 保留区间尾部 → 批准文字 → 声音与必要限制。

完整商品分析、创意比较、选择理由、审批规则和其他段的全部脚本只留在方案，不整份传给模型。共同商品细节在本段只写一次，动作、批准台词及图文保留原文；不机械截断、去重单词或删除重要事件。连续性增加了必要信息，不能承诺每一种多段方案的提示词都比旧版更短。

新模板把 `entry_state/exit_state` 同时写入分镜与视频提示词，避免只在报告显示、模型实际未收到。独立关键帧策略也把对应边界状态写入首个/末个关键帧提示。

## 全片声音：文字统一，不强制文件参考

继续默认 `audio.mode=video`。在 `audio.shared` 定义全片 `voice/music/ambience`，每段 `audio` 主要填写自己的 `speech_text`，动作声继续写 `sfx`。若 shared 省略，脚本复用片段中首个相应描述并填入其余段，不为每段重新选择声音。默认补全只是兜底；导演仍须给出适合本广告的具体音色、语速、音乐风格与节奏。

```json
{
  "audio": {
    "mode": "video",
    "shared": {
      "voice": "自然温暖的成年女声，中等语速，克制表达",
      "music": "轻柔电子节奏，96 BPM，少量温暖键盘音色",
      "ambience": "安静室内，轻微而稳定的空间混响"
    }
  }
}
```

同一角色/音乐/环境描述若局部不同，prepare 会指出差异。先由 AI 判断是否只是措辞不一致；是则统一描述。若确实按剧情变化，在该段 `audio.change_reason` 写明原因，例如室内转户外。脚本不会自行判断两种文字描述语义相同，也不会擅自覆盖不同设计。

有多个说话人时，`audio.speakers` 用稳定 ID 对应各自音色，片段 `audio.speaker_id` 引用该 ID；默认 narrator 使用 shared.voice。逐镜模式仍使用各 `shots[].audio` 的独立台词；展开后继承全片声音，不重复整段文稿。无台词段不得新增人声。

中间段提示继续相同声音方向，不重新起奏、不重复开场音效、不提前收尾。最后一段允许脚本安排收束。独立语音仍只在用户明确要求时启用；本次优化不添加音频上传、音色克隆或独立配乐服务。

以上是减少差异的提示约束，不能保证不同请求输出同一音色/旋律。验收以短广告整体协调、台词完整、没有明显换人或突兀断裂为准。

## 相邻分镜：区分切镜与动作接力

- 默认 `transition_mode=cut`：正常切镜可以改变构图、景别、场景，保持身份与美术，不强求首尾画面重合。
- `transition_mode=match_action`：明确需要同一动作继续时，后段省略 `entry_state`，自动继承前段 `exit_state`；也可填写完全相同的共享边界描述。不同描述会提示统一，避免两处对同一接力状态各写一套。
- `match_action` 只表示导演意图和提示词联系，不会上传末帧、创建依赖或宣称真实接续成功。已有 `continuity_from` 才是受通道资格限制的实际末帧接续，两者不混同。

AI 在现有看图环节同时查看相邻分镜，检查手持状态、商品开合/朝向、动作阶段、移动方向、服装、光线；前后文只是边界参考，不让视频额外重演前一段或提前演下一段。无需新增审阅布尔字段或用户确认。

## 提示词长度检查

不同服务商、模型与图片/视频接口可以有不同上限。安装配置时由 AI 核对实际文档，在视频配置的 `prompt_limits` 中按 `provider:model` 登记；也可由本次 `plan.prompt_limits` 提供整个映射。每条必须有 `max_characters` 和/或 `max_utf8_bytes`、`source`、`checked_at`。字符与 UTF-8 字节分别计数；不拿字符数冒充 token 数。

维护命令：`commercial_ad.py configure --model MODEL --prompt-limits PATH_TO_JSON`，文件是“通道 ID → 限制规则”的 JSON 映射。省略该参数时保留已有登记。数值必须来自该通道资料，不照抄其他供应商、不设置猜测默认值。计划中的映射优先于本地默认映射，并在第一次批准时冻结。自动备用通道也分别检查。

独立图片 API 配置可增加同结构的单条 `prompt_limit`；它随图片配置冻结。内置 imagegen 当前未配置数字上限，不冒充已验证。

prepare 会写 `prompt-check.json`，逐项记录字符数、UTF-8 字节数、限制依据和检查状态。已知超限在方案准备阶段阻止继续，并在实际提交前再次检查；未知上限标记 `limit_unknown`，不冒充服务商保证，也不凭空阻塞所有正常订单。方案报告同步显示未知数量。

超限时 AI 在付费前精简重复描述，保留镜头顺序、关键动作、身份、台词及图文，重新 prepare。已批准项目不能自动改提示词再收费；沿现有修订确认规则处理。长度合规不能证明供应商任务必定成功，通用失败不能直接归因于提示词过长。
